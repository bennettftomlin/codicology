# Codicology audit — 2026-11-10

**Scope.** `src/codicology` (14,978 lines; `pipeline.py` is 11,171 of them),
the tests (60 files, 1,038 tests), the Calibre plugin, `tools/`,
`pyproject.toml`, and the environment the plugin runs: Python 3.13.16 with
`surya-ocr==0.22.1`.

**Method.** I profiled a warm rebuild, timed the suspects, and compared the
installed packages against Surya's requirements. Six read-only review passes
then read every source file in full, one region each, and I re-checked the
findings that matter most. Each finding carries its standing:

- **measured** — timed or counted on a real book or the real environment
- **verified** — I read the code or ran a small reproduction myself
- **reader** — found by a review pass with its own evidence (a snippet run on
  synthetic input, or the code read); not re-checked by me

Line numbers are today's where I re-checked them. Reader findings predate
today's edits to `pipeline.py`, so those name the function instead.

Nothing was changed for this audit. The four fixes in §1 were made the same
day for other reasons. They are committed, and so is the guard row 4 below
asks for, which was written after the audit was.

Rows 1, 2, 3, 5, 6 and 10 of the list below, and a handful of the smaller
findings, were worked through later the same day. §1a records what was
done, what it measured, and where the work showed this audit to be wrong.

### 2.2 Decisions and review

- **Wrong machine rows have no way out (seen).** Decisions files hold ladder
  rows that never applied only because the old applier could not match a dash.
  The new one can. Two of them would damage the page: 4334 p178 `a-or` → `or` (the `a` is the letter of note 11a)
  and 9559 p310 `Glavlit-some` → `Glavit-some`. I moved those two into a
  `retired` list in their files; nothing reads that key yet. Needed: a
  `retired` list the tools honour and the sheet can write, and a rule that a
  machine row which removes characters next to a digit or dash goes to the
  reviewer.
- **A second review round overwrites the first (verified).** Exporting again
  replaces the decisions file; applying in place again overwrites `.preapply`
  (`review.py:1099`), so the original is lost after two rounds.
- **A long deletion can never apply (verified).** A `delete_run`'s text is cut
  at 2,000 characters when the sheet is written (`adjudicate.py:1070`), so it
  no longer matches the page.
- **Run crops are cut from the wrong page (verified).** `_run_crops` uses the
  book page (`review.py:248`) where `crop_data_uris` uses `pdf_page` (179).
  Wrong wherever blank pages were dropped.
- **Old sheets are still in the plugin cache (seen).** Their export writes
  unaddressed rows. The new applier is safe with them but most go stale; the
  plugin does not say that re-adjudicating fixes it.
- **Two-column pages produce false disputes (seen).** On tables and index
  pages the witnesses are aligned across columns (5497 p12
  "November/December", 1108 p195 "for/first"). Both were reviewed in good
  faith and both corrections were wrong. Align per layout block, or skip pages
  the layout marks as table or index.
- **`apply_decisions` rewrites every zip entry (verified, `review.py:1118`).**
  Harmless, but untouched entries are no longer byte-identical, which makes
  "what changed" harder to prove.

## 3. Performance

Warm rebuild of Kill or Get Killed: 440 pages, 364 figures, every page already
in the OCR cache. **201.6 s** (measured, profiled).

| Where | Seconds | What it is |
|---|---|---|
| `load_pages_from_pdf` | 126.3 | 107.1 in `Image.save` for 440 page PNGs, 12.3 rendering |
| `emit_figure` | 64.9 | 46.7 in 716 `Image.save` calls, 14.2 in `better_figure` |
| everything else | about 10 | all text passes together (notes, contents, folios, index, typography) are under 3 |

Pillow's encoder is 153 s, 76% of the run.

### 3.1 Page PNGs are encoded only to be hashed (measured)

The OCR cache key is the SHA-256 of the page's PNG file. On a warm build the
PNGs are otherwise barely opened. Two changes, independent:

- **Render in worker processes**, each opening the PDF itself. 8 workers gave
  byte-identical PNGs, so keys do not change: 34.1 s → 6.2 s on 64 pages of
  Reconstruction (5.5×), 17.7 s → 3.5 s on Kill or Get Killed (5.0×).
- **Key on something else**: a hash of the pixels, or (PDF hash, page index,
  render recipe). A warm build could then skip encoding altogether. This needs
  a one-time migration pass that re-keys existing caches while today's encoder
  is still installed. See §4.2 for why it should not wait.

Smaller, same function: `get_bitmap()` is called only for the page's
dimensions, 8.0 ms per page against 0.005 ms for `get_px_size()`. All six
sampled pages were grey-only yet written as RGB. Kill or Get Killed's
JBIG2 pages are placed with a flipped matrix, so all 373 are rendered at 300
dpi instead of extracted as 28–44 KB bilevel images; changing that alters the
OCR input and needs a shelf check.

### 3.2 Figures are encoded twice (measured)

Each figure is saved as JPEG and as `optimize=True` PNG, and the smaller kept.
356 of 358 end as JPEG. On 60 figures: JPEG 2 ms, optimised PNG 290 ms, PNG at
level 1 31 ms. Skipping the optimised PNG when the level-1 PNG is more than
twice the JPEG skipped 58 of 60 with no wrong choice.

### 3.3 Region renders rasterise the whole page (reader, timed on synthetic)

`_render_region` renders the full page at up to 8× and crops. pypdfium2 5.12
takes `crop=` directly: 8–14 ms against 48–163 ms. The source PDF is also
re-opened per figure and per page by `better_figure` and the two `recover_*`
passes; open it once per build.

### 3.4 The OCR cache file (measured and reader)

Kill or Get Killed's cache is 71.7 MB raw, of which 70.4 MB is base64 figure
JPEGs and 0.75 MB is the text. Every checkpoint (each 25 pages of a live read)
re-gzips the whole file at level 9: 2.4 s here, 16.2 s on a 254 MB cache
(reader). `OCRCache.get` decodes every figure although two of its three
callers ignore the pixels. A truncated file raises an uncaught `EOFError`.
Moving figures out of the JSON into files beside it fixes all four;
`compresslevel=1` is the interim. The plugin cache is 2.5 GB across 151 books
and is never pruned: replacing a PDF or deleting a book strands its cache.

### 3.5 Tesseract (verified and reader)

Adjudication renders, encodes and reads one page at a time and keeps nothing
between runs. I watched a live job run one tesseract process at a time on a
10-core machine for over 8 minutes. A process pool and a stored TSV per page
would make it several times faster and make re-adjudication nearly free. In
the build, three wrappers launch the same recognition separately — up to four
subprocesses per page — because their cache keys differ (reader).

### 3.6 Searchable PDF (reader, timed)

One `insert_text` call per word: 0.39 s and 88 KB per page against 0.02 s and
2.8 KB with one `TextWriter` per page. The text-layer pass also re-embeds
every page image the checkpoint PDF already holds (0.26 s per page against
0.002 s to open the checkpoint and add text), and holds every decoded figure
in memory though it reads none.

### 3.7 Server start and offline builds (seen)

A build with every page cached still launches `llama-server`. Start it on the
first cache miss. A `--cache-only` flag that fails rather than reads would let
the tool promise "this rebuild will not run Surya"; today that depends on the
cache happening to be complete.

### 3.8 Capture (reader)

A video is fully decoded twice, and stride-skipped frames are decoded rather
than grabbed. Burst photos are decoded up to three times each. The rectifier
runs two tesseract passes per photographed page.

### 3.9 Tests (measured)

1,038 tests in 87 s, of which **48.9 s is one test**:
`test_page_identity.py::test_single_small_illustration_does_not_become_the_page`
loads all 227 pages of a PDF to inspect page 25. The next slowest is 1.3 s.
Giving the loader a page range would bring the suite under 40 s;
`pytest-xdist` (MIT, one dependency) would cut it further. Five test files
reference absolute paths under `/Users/Bennett1`.

1. **OpenCV (measured).** The two wheels install into the same `cv2`
   directory, and the unpinned one won: Surya and codicology both run on
   OpenCV 5.0.0 while `pip check` reports nothing. The source makes no GUI
   call; `cv2.VideoCapture`, which it does use, is in the headless wheel.
   Depend on `opencv-python-headless` with no version of its own.
   `doctor.py` checks the distribution name `opencv-python` and should compare
   `cv2.__version__` with Surya's pin instead.
2. **Pillow's ceiling holds the cache together (inferred).** Because the cache
   key is a hash of PNG bytes, any change to the encoder orphans every
   rendered page's reading. Pillow 11.1 moved its wheels to zlib-ng, so the
   bytes will almost certainly change when Surya lifts `pillow<11`. Re-keying
   (§3.1) should happen before that day, not after.

### 5.1 One tokeniser

`adjudicate.WORD` accepts `A-Za-zÀ-ÖØ-öø-ÿŒœ`. A word with a macron, a háček,
a Greek letter or a combining accent is cut at that character, and the sheet
then disputes a fragment: `Kenky` for Kenkyū (1996), `techn` for technē
(9482), `ambici` (5498). A reviewer who types the whole word for a fragment
gets a correction the applier must refuse. In `pipeline.py` the guards go
further and count only ASCII (§2.1). One shared pattern,
`\p{L}[\p{L}\p{M}'’\-]*` with the `regex` module, fixes both. The sheet and
the applier must change together, because an addressed row stores tokens;
existing decisions files would need the same one-time re-addressing the
occurrence fix did.
